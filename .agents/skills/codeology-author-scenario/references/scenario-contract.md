# Scenario contract

A scenario should define:

- stable ID, version, title and difficulty;
- job-task statement and inherited context;
- prerequisites and mapped skills;
- functional and non-functional acceptance criteria;
- allowed tools and open-tool/AI policy;
- starter repository and licence provenance;
- public checks and submission manifest;
- versioned rubric with criterion evidence anchors;
- assurance ceiling and escalation conditions;
- expected artifacts and employer-readable evidence;
- deterministic validation fixtures.

Prefer overlapping skills across several scenarios so durable claims are supported by varied evidence.
